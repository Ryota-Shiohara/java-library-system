# kumpei 実装計画書

## 1. 担当の目的

kumpeiは「会員と貸出返却を正しく管理し、利用者がGUIから迷わず操作できる機能」を担当する。モデル、業務ロジック、永続化連携、GUI、JUnitテストを一通り受け持ち、実装上の中心機能である貸出フローを完成させる。

想定作業時間は約25時間とする。

## 2. 主担当範囲

### 会員・貸出モデル

- `Member`モデルを実装する。
- 会員IDと氏名を保持し、空文字や不正な値を拒否する。
- `Loan`モデルを実装する。
- 貸出ID、本ID、会員ID、貸出日、返却期限を保持する。
- 必要に応じて返却済み履歴を残すか、アクティブ貸出だけを保存するかを共同設計で決める。

### 会員管理と貸出返却

- 会員の追加、修正、削除、一覧、検索を実装する。
- 会員ごとに借りている本のタイトルを確認できるようにする。
- 本ごとに借用者を確認できるようにする。
- 本と会員の存在、利用可能冊数を確認してから貸出を成立させる。
- 返却対象が存在する場合だけ返却を成立させる。
- 貸出中の会員を削除できないようにする。
- 在庫0、重複貸出、不明ID、二重返却を拒否する。
- 14日後の返却期限と延滞判定を実装する。

### 永続化連携

- ryotaが作成する共通I/Oを利用して会員・貸出を保存する。
- 読込時に参照先の本・会員が存在することを確認する。
- 貸出処理失敗時に途中状態を保存しない。
- 保存・再読込後も借用者照会と借用一覧が一致することを確認する。

### GUI

- Membersタブの一覧テーブルを実装する。
- 会員のAdd、Edit、Delete、Search、Clear操作を実装する。
- Loansタブの貸出一覧を実装する。
- Checkout、Return、Show Borrower操作を実装する。
- 本と会員を選択する貸出ダイアログを実装する。
- 返却期限と延滞状態を分かりやすく表示する。
- すべての画面表示とエラーメッセージを英語にする。

## 4. JUnitテスト

kumpeiは次のテストを主担当とする。

### Member

- 正しい値で会員を生成できる。
- 会員IDまたは氏名が空の場合に失敗する。
- 会員IDの重複登録を拒否する。
- 貸出のない会員を修正・削除できる。
- 貸出中の会員を削除できない。

### LoanService

- 在庫がある本を登録済み会員へ貸し出せる。
- 貸出後に利用可能冊数が1減る。
- 返却後に利用可能冊数が1増える。
- 本から借用者を取得できる。
- 会員から借りている本を取得できる。
- 在庫0の場合に貸出を拒否する。
- 存在しない本または会員への貸出を拒否する。
- 同一会員による同一本の重複貸出を拒否する。
- 存在しない貸出の返却と二重返却を拒否する。
- 失敗した貸出・返却の後に本、会員、貸出の状態が変わらない。
- 返却期限と延滞判定が境界日で正しく動く。

### 統合テスト

- 本と会員を登録し、貸出、保存、再読込、返却まで完了できる。
- 複数会員が同じタイトルの別冊を借りられる。
- 全冊貸出後は次の貸出だけが拒否される。
- 読込後の借用者照会と会員の借用一覧が一致する。

日付依存テストでは`LocalDate.now()`を直接呼ばず、Serviceへ`Clock`を注入して固定日時で検証する。

## 7. ryotaへ要求する契約

- 本IDから本の表示名と利用可能冊数を取得できること。
- 貸出・返却時に在庫の整合性を一つのService操作として保てること。
- Books画面を更新する公開メソッドまたはイベントを提供すること。
- ファイル保存が成功した場合だけ操作完了として扱えること。
- テスト用にメモリ上のRepositoryまたは一時ディレクトリを注入できること。

## 8. レビュー観点

ryotaのコードについて、次を確認する。

- 本の所有冊数と貸出中冊数の不変条件が守られること。
- 本の削除・修正が貸出情報を壊さないこと。
- ファイルがない初回起動で正常に動くこと。
- 保存失敗を握りつぶさずGUIへ通知できること。
- GUIがServiceを経由して状態を更新していること。
- 本番コードにJUnitなどJava SE外の依存が混入していないこと。
- コメント、Javadoc、テスト名、TODO、ログ、サンプルデータにも日本語がないこと。
